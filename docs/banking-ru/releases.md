# Версии и фиксация банковских задач

Решение 11 ноября 2026: Bank 2 v42 фиксируется как исходная точка дальнейшей
разработки. В [реестре прохождений](results.md) сохранены провалы Sol/Astra v41
и Astra v42. Провал Sol на v42 пока не измерен. Фиксация не разрешает новые
модельные попытки и не объявляет все остальные задачи провалидированными.

## Что замораживается

Релиз — неизменяемый Git-тег `bank-002-v42` и manifest SHA256 в
`releases/banking_ru/bank_002/v42.json`. В него входят Bank 2, общие данные и
корпус, runtime/оценщик, harness, зависимости и предметная документация.
Сценарные тексты остаются в private store; Git хранит ссылки и хеши, а runtime
проверяет их при загрузке. Для воспроизведения нужны и тег, и соответствующий
закрытый store. Сам Git-тег не заменяет хранение payloads и журнала.

Старые manifest, теги, результаты и архивы запрещено перезаписывать. Нельзя
менять тикет, статьи, политики, ответы инструментов, данные, критерии или
зависимости и продолжать называть полученный снимок тем же релизом.
Даже исправление дефекта требует новой версии и записи о влиянии на оценку.
Редакционные дополнения к реестру результатов и процессу разработки допустимы;
они не изменяют материалы, доступные проверяемому агенту.

Manifest фиксирует состояние при выпуске. Исторические прогоны v41/v42 были
выполнены до коммита; их отчёты не переименовываются в прогоны точного release
commit. Новый tag задаёт воспроизводимую базу для следующих разрешённых измерений.

## Рабочий цикл

1. Начать от актуального `main`, создать короткую ветку `task/bank-NNN-<цель>`;
   для общего кода — `fix/banking-<цель>` или `feat/banking-<цель>`.
2. Менять одну задачу/механизм. Старый релиз брать из тега, не редактировать его
   файлы manifest и результаты. Общую среду не раздваивать по ID задачи.
3. Если меняются зависимости Bank 2, оформить новый snapshot, например v43.
   Это требуется и при изменении общего API ради другой задачи. Результаты
   прежней версии не наследуются как измеренные результаты новой.
4. Проверить корректный и допустимый альтернативный пути, бездействие и
   существенные ошибки; проверить контракты, изоляцию при изменении harness,
   хеши и документацию. Полная регрессия и модельные запуски — только в явно
   разрешённом объёме. Непроверенное влияние на другие задачи указать отдельно.
5. Commit → review diff и проверок → merge в main → обычный push без force.
   PR удобен при нескольких разработчиках; при работе одного автора допустимо
   проверенное локальное слияние. Push выполняется по разрешению пользователя.
6. Создать новый неизменяемый тег на принятом commit, опубликовать тег и main.
   Дальнейшая работа начинается новой веткой. Постоянная ветка dev не нужна.

## Проверка снимка

`uv run python scripts/banking_ru/check_frozen_bank2.py` сверяет текущую базу с
активным manifest, включая добавления и удаления файлов в закреплённых областях.
Проверка без модели включена в CI. Для нового снимка после адресной валидации:

```sh
uv run python scripts/banking_ru/check_frozen_bank2.py --create v43
uv run python scripts/banking_ru/check_frozen_bank2.py
```

Команда создания не перезаписывает существующие версии. В diff должны быть
новый manifest и изменение `current.json`; старый manifest остаётся прежним.
CI отдельно запрещает изменения/удаления опубликованных manifest и записей
прогонов относительно базы PR/push. Сам факт успешной проверки хешей не заменяет
проверку решаемости или измерение сложности.

Рекомендуемая защита GitHub: запрет force-push/deletion для main и тегов
`bank-*-v*`, обязательный freeze-check перед merge. Правила GitHub должны быть
настроены отдельно: наличие workflow само по себе не включает branch protection.

## Проверка исходного выпуска v42

11 ноября 2026 перед публикацией: 112 адресных тестов Bank 2, плановых сообщений
и брокера; 7 тестов генератора identity; структурная проверка 61 задачи и
контракты confidentiality/access/identity/discovery прошли. Генераторы приведены
в соответствие с существующим стартом с подтверждённой личностью: проверяется
реальное исходное состояние, а не заявление в тикете. Задача/оценщик этой правкой
не менялись. Ruff проверен для всех Python-файлов релизного diff.

Freeze-check закрепляет 499 файлов; на временном репозитории проверены изменение,
добавление, удаление зависимости и запрет перезаписи прежнего manifest.
Полная регрессия остальных задач и новые модельные прогоны не выполнялись.
Выпуск включает накопленные изменения общей среды v30→v42; адресная проверка
Bank 2 не означает подтверждённую корректность всех остальных задач.
